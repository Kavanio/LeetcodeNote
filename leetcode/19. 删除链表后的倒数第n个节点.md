
## 解题代码
```java
class Solution {
	public ListNode removeNthFromEnd(ListNode head, int n) {
		ListNode dummy = new ListNode(0);
		dummy.next = head;
		
		ListNode slow = dummy, fast = dummy;
		
		for(int i = 0; i <= n; i++) {
			fast = fast.next;
		}
		
		while(fast != null) {
			slow = slow.next;
			fast = fast.next;
		}
		
		slow.next = slow.nxt.next;
		
		return dummy.next;
	}
}
```


## 解题思路
我最开始想到的题解思路是：
既然单向链表只能从前往后遍历，没办法直接从尾部往前找，那么能不能先遍历一次链表，计算出链表的总长度L，再通过L - n找到需要删除节点的前一个节点，最后通过修改 next 指针完成删除。
这个思路是可行的，但是需要遍历俩次链表。
但是这道题我们使用：**快慢指针的思路**
快慢指针的核心思想，就是让 fast 先走 n + 1步，然后fast 和 slow 再一起往后移动，这样俩个指针之间就始终保持着固定的距离。
例如：
1 -> 2 -> 3 -> 4 -> 5 -> null
假设 n = 2，我们需要删除节点4.但是删除节点并不需要直接找到节点4，而是应该找到他的前一个节点 3，然后执行：`slow.next = slow.next.next`
这样就相当于让节点3跳过节点4，直接指向节点5。
**为什么fast要先走 n + 1步呢，而不是 n 步？**
因为如果 fast 只领先 slow 俩步，那么 fast 到达 null 时，slow 恰好停在节点 4，但我们真正需要的节点是节点3.因此让 fast 多领先一步，也就是 n + 1步，这样最后 slow就能停在待删除节点的前一个位置/
这里还需要考虑一个特殊情况：**如果删除的就是头节点怎么办？**
例如链表 1 -> 2 ->3，要求删除倒数第3个节点，也就是节点1.
因此可以引入一个虚拟头节点 dumpy，让它指向原来的 head，然后让 fast 和 slow 都从 dummy 出发。这样即使需要删除的是原来的头节点，slow 最后也能停在 dummy 上，仍然可以通过 slow.next = slow.next.next 完成删除。不需要额外的进行条件判断。
最后返回 dummy.nex，而不是 原来的head，因为删除头节点之后，原来的 head 可能已经不是新链表的头节点了。
