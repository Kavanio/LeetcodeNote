
## 解题代码
```java
class Solution {
	public ListNode sortList(ListNode head) {
		
		// 递归终止条件
		if(head == null || head.next == null) return head;
		
		// 快慢指针寻找中点
		ListNode slow = head;
		ListNodee fast = head.next;
		
		while(fast != null && fast.next != null) {
			slow = slow.next;
			fast = fast.next.next;
		}
		
		// 将链表拆分成左右俩个部分
		ListNode right = slow.next;
		slow.next = null;
		
		// 对左右链表进行排序
		ListNode left = sortList(head);
		right = sortList(right);
		
		// 合并俩个有序链表
		return merge(left, right);
	}
	
	
	private ListNode merge(ListNode l1, ListNode l2) {
		ListNode dummy = new ListNdoe(0);
		ListNode tail = dummy;
		
		while(l1 != null && l2 != null) {
			if(l1.val < l2.val) {
				tail.next = l1;
				l1 = l1.next;
			} else {
				tail.next = l2;
				l2 = l2.next;
			}
			
			tail = tail.next;
		}
		
		return dummy.next;
	}
}
```

## 解题思路
这道题使用的是归并排序，核心思路就是：**先拆分，再排序，最后合并**
因为链表不像数字，不能直接通过下标直接访问元素，所以我不需要想着怎么一次性把整个链表排序好，而是先把它从中间拆成左右俩个部分，再分别对左右来个部分进行排序。
比如有一条链表：
```
4 -> 2 -> 1 -> 3
```
首先通过快慢指针找到该链表的中点，拆成：
- 4 -> 2
- 1 -> 3
然后对左右俩个部分继续递归拆分，直到每条链表都只剩下一个节点。
因为只有一个节点的链表，本身就是有序的，所以不需要继续排序，直接返回这个节点即可。
接下来，在递归返回的过程中，通过 merge 把俩个有序链表合并起来。
比如：
- 4 和 2 合并，最终变成了：2 -> 4
所以要理解，递归本身不是载直接排序，而是在不断拆分链表。真正发生排序的是在递归返回时执行的 merge。

### 为什么快慢指针不是从同一个位置出发？
```java
ListNode slow = head;
ListNode fast = head.next;
```
之前学习快慢指针的时候，通常都是让 slow 和 fast 从 head 开始，但这道题为什么不一样？
主要是因为我们希望 slow **最后停在左半部分的最后一个节点，** 这样才能直接通过 slow,next = null 把链表断开。
假设链表是：
```
4 -> 2 -> 1 -> 3
```
如果俩个指针都从 head 出发，最终 slow 会停在节点1.
这时候断开链表，就会变成：
- 左边：4 -> 2 -> 1
- 右边：3
虽然这样也能拆分，但问题在于，如果链表只有俩个节点：4 -> 2

那么 slow 最后会停在节点2，此时 slow.next 已经是 null，左半部分仍然是 4 -> 2。
这样递归时，链表的长度始终没有减少，就会不断重复调用自己，最后发生栈溢出。
所以这里让：
```java
ListNode fast = head.next;
```
相当于快慢指针一步。
这样对于偶数长度的链表，slow 会停在中间节点的一个。
**所以快慢指针并不是必须要从同一个位置出发，而是要看我们慢指针最后停在什么地方**

整个过程可以理解成：**递归往下走，不断把大链表拆成小链表；递归往回返回时，不断把小链表的有序链表合并成更大的有序链表。**
